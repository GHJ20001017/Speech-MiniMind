# 00. 语音基础：从波形到频谱

这一章不使用 PyTorch，只使用 Python、NumPy 和 Matplotlib。目标不是马上训练模型，而是回答一个更基础的问题：**计算机到底如何表示和观察一段声音？**

语音不是“文字的另一种文件格式”。人说话时，声带和口腔使空气产生连续的压力变化；麦克风把压力变化转换成电信号；声卡再把电信号测量成一串数字。语音模型看到的，最终就是这串数字。

## 1. 从空气振动到数字

真实声音是连续信号，可以写成随时间变化的函数 `x(t)`。计算机不能保存无限多个时间点，因此每隔固定时间测量一次：

```text
x[0], x[1], x[2], ..., x[N-1]
```

这些离散的数称为**采样点（sample）**。如果每秒采样 16000 次，就称采样率为 16 kHz。第 `n` 个采样点对应的时间是 `t[n] = n / sample_rate`。

## 2. WAV 文件里有什么

WAV 是一种容器格式，常见的 PCM WAV 直接保存采样数字。最重要的三个参数是：

- **采样率**：每秒记录多少个采样点。示例音频是 24000 Hz。
- **位深**：每个采样点使用多少位保存。16-bit PCM 的整数范围是 `-32768` 到 `32767`。
- **通道数**：单声道为 1，立体声通常为 2。

16-bit PCM 文件中的整数会被转换成浮点数：

```text
x_float = x_int16 / 32768
```

这样数值大致落在 `[-1, 1]`，不同音频的数值范围更容易比较。脚本读取 WAV 后就在这里完成归一化。

## 3. 采样率与 Nyquist 定理

采样率太低时，一个高频信号可能看起来像另一个低频信号，这种错误叫**混叠（aliasing）**。Nyquist 采样定理告诉我们：采样率为 `Fs` 时，能够无歧义表示的最高频率约为 `Fs / 2`。

```text
16 kHz → 最高约 8 kHz
24 kHz → 最高约 12 kHz
```

人类语音的重要信息大多在 8 kHz 以内，因此 16 kHz 常用于 ASR；更高采样率保留更多高频细节，但也带来更长的序列和更高的计算成本。

## 4. 波形：时域中的声音

把采样点按时间排列，就得到**波形（waveform）**。横轴是时间，纵轴是归一化振幅：

- 振幅正负表示压力变化的方向，不代表正负音量。
- 振幅绝对值较大通常意味着瞬时能量较高，但不等同于人耳感知的响度。
- 说话段通常有明显的振荡，静音段接近 0；背景噪声会让静音段也不完全平直。

## 5. RMS：观察能量大小

均方根（Root Mean Square）用一个数字描述一段信号的平均能量：

```text
RMS = sqrt(mean(x[n]^2))
```

平方消除了正负振幅抵消的问题，再开平方使结果回到原来的量纲。当前脚本计算整段音频的全局 RMS；真正的语音处理通常会在 20～30 ms 的短窗口内计算短时 RMS，用于静音检测或 VAD。

## 6. 过零率：观察振荡快慢

过零率（Zero-Crossing Rate, ZCR）表示相邻采样点的符号发生变化的比例：

```text
ZCR = sign_changes / (number_of_samples - 1)
```

频率较高、噪声较多的信号通常更容易穿过 0，因此 ZCR 往往更高；浊音和低频成分较强的片段通常更低。它不是现代 ASR 的主要特征，但适合作为第一个简单的时域指标。

## 7. 为什么不能直接“看”频率

波形回答的是：**某一个时刻，振幅是多少？** 但我们还想知道：**这段声音由哪些频率组成？** 频谱就是把随时间变化的振幅换一种坐标表示，展示各个频率成分的强弱。

## 8. FFT 前为什么要加窗

这里的“周期信号”不是说真实的语音一定会周期重复，而是 **DFT 对有限长度序列的数学解释**：它把这 `N` 个采样点看成一个周期的内容，并在左右两端不断复制：

```text
x[0], x[1], ..., x[N-1], x[0], x[1], ..., x[N-1], ...
```

因此，DFT 实际上会检查“如果把这段片段首尾相接并无限重复，它包含哪些频率”。如果 `x[N-1]` 和 `x[0]` 数值差别很大，重复处就会出现突然跳变。例如：

```text
片段结尾：  0.80, 0.85, 0.90
片段开头： -0.10,-0.05, 0.00
```

周期拼接后会从 `0.90` 瞬间跳到 `-0.10`。这种尖锐的跳变本身包含很多高频成分，所以频谱中会出现原信号并没有的额外频率，这叫**频谱泄漏（spectral leakage）**。它不是 FFT 算错了，而是 FFT 正确地分析了“带有边界跳变的周期延拓信号”。

为了减小这个人为的跳变，通常在 FFT 前乘一个两端接近 0 的窗函数。当前脚本使用 Hann 窗：

```text
w[n] = 0.5 - 0.5 * cos(2πn / (N - 1))
x_windowed[n] = x[n] * w[n]
```

Hann 窗在片段两端接近 0，中间接近 1。加窗后，周期拼接处的两端都接近 0，跳变明显减小。脚本第二幅图是窗函数本身，第三幅图是实际送入 FFT 的加窗波形。

窗函数也不是免费的：它会降低片段两端的信号能量，并使频谱峰变宽。因此窗函数是在“减少泄漏”和“保持频率分辨率”之间的折中；Hann 窗是语音处理中常用的默认选择。

## 9. FFT 到底输出了什么

对长度为 `N` 的波形做离散傅里叶变换（DFT），可以理解为拿许多不同频率的正弦波和余弦波去匹配输入信号。FFT（Fast Fourier Transform）是快速计算 DFT 的算法。

FFT 输出 `X[k]` 是复数：

```text
X[k] = real[k] + j * imag[k]
```

每个频率 bin 包含：

- **幅度**：该频率成分有多强，`|X[k]| = sqrt(real[k]^2 + imag[k]^2)`。
- **相位**：该频率成分在时间上的偏移，`angle(X[k])`。

当前脚本绘制的是 `abs(np.fft.rfft(...))`，因此看到的是幅度，没有绘制相位。第 `k` 个频率 bin 对应 `k * sample_rate / N`，频率分辨率是 `sample_rate / N`。

## 10. 为什么只画一半频率

输入波形是实数时，FFT 的负频率部分与正频率部分互为共轭，包含重复信息。因此脚本使用 `rfft`，只保留从 0 Hz 到 `sample_rate / 2` 的部分。示例音频采样率为 24 kHz，所以 Nyquist 频率是 12 kHz；绘图默认将显示范围限制在 8 kHz 以内，以聚焦语音。

## 11. 从采样点到频谱：完整中间产物

运行：

```bash
python scripts/analyze_audio.py examples/disgusted_to_happy.wav --plot outputs/example.png
```

图中四个面板依次展示：

```text
PCM 整数采样点
    ↓ 除以 32768
归一化波形 x[n]
    ↓ 乘以 Hann 窗
加窗波形 x[n] · w[n]
    ↓ FFT
复数频域系数 X[k]
    ↓ 取绝对值
幅度频谱 |X[k]|
```

1. **Normalized waveform**：从 PCM 整数归一化得到的 `x[n]`。
2. **Hann window**：即将乘到波形上的 `w[n]`。
3. **Windowed waveform**：FFT 的真实输入 `x[n] * w[n]`。
4. **Magnitude spectrum**：FFT 结果取绝对值得到的 `|X[k]|`，并转为 dB 绘制。

终端还会打印采样率、采样点数量、时长、峰值振幅、RMS、过零率、FFT bin 数和频率分辨率。

## 12. 频谱与时频谱的区别

当前脚本只对整段音频做一次 FFT，因此得到的是一维总体频谱。它可以告诉我们“整段音频总体上有哪些频率”，但无法告诉我们“某个频率在第几秒出现”。

语音是随时间变化的，而且整句话通常并不是一个稳定的信号。元音、辅音、停顿会不断切换。因此我们把长音频切成许多较短的片段，在每个片段内近似认为信号的频率结构不会变化太快，这叫**短时平稳性（short-time stationarity）**。

这就是滑动窗口的来源。窗口有三个常见参数：

- **窗长（frame length）**：每个片段包含多少采样点，例如 25 ms。
- **帧移（hop length）**：窗口每次向前移动多少采样点，例如 10 ms。
- **重叠（overlap）**：相邻窗口重叠的部分。25 ms 窗长、10 ms 帧移意味着 15 ms 重叠。

窗口通常会重叠，因为如果每一帧完全不重叠，两个窗口交界处的信息会被切断；重叠可以让时间变化更连续，也降低边界对结果的影响。

在每个窗口内，我们仍然会乘 Hann 窗。它的作用不是“保证窗口内的信号是周期的”，而是让这个窗口在进行周期延拓时，首尾更平滑：

```text
长语音
  → 取第 1 个短窗口 → Hann 窗 → FFT
  → 向右移动 hop   → Hann 窗 → FFT
  → 向右移动 hop   → Hann 窗 → FFT
  → 把每帧频谱按时间排列
```

所以需要区分两件事：

1. **滑动窗口**：把变化很快的长语音变成一系列短时、近似稳定的分析片段。
2. **窗函数**：减少每个片段在周期延拓时的边界跳变和频谱泄漏。

语音信号本身仍然不一定周期，窗函数也不能让它变成真正的周期信号。

短时傅里叶变换（STFT）的过程是：

```text
波形 → 切成许多短帧 → 每帧加窗 → 每帧 FFT → 按时间排列 → 二维时频谱
```

常见语音模型还会继续计算功率、通过 Mel 滤波器组并取对数：

```text
STFT → |X|² → Mel filter bank → log-Mel spectrogram
```

这就是下一章要实现的内容。届时特征会从一维波形变成类似“图片”的二维张量，随后才能交给 Conformer 或 Transformer 声学编码器。

## 13. 动手实验

建议每次只改变一个因素：

1. 把音频音量乘以 0.5，观察峰值和 RMS 如何变化。
2. 截取一段静音和一段语音，比较它们的波形、RMS 和频谱。
3. 将采样率改成 16 kHz，观察 Nyquist 频率和频谱范围的变化。
4. 暂时去掉 Hann 窗，对比加窗前后的频谱泄漏。
5. 对一段短纯音运行脚本，观察频谱峰值是否出现在预期频率附近。
